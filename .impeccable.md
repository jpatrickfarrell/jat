## Design Context

### Users
Power users and developers who run JAT — a self-contained environment for multi-agent coding work. They spawn multiple AI agents in parallel, supervise or step away while agents ship, and use the IDE as a live control surface for tasks, sessions, events, and code. They are technical, opinionated, and spend all day in the tool. Their job-to-be-done is *"see everything my swarm is doing, stay oriented, and jump in when something needs me."* Information density and signal fidelity matter more than beginner-friendly onboarding.

### Brand Personality
**Cockpit. Instrument. Supervisory.**

- **Voice/tone**: Direct, confident, no hand-holding. Assumes expertise. Labels are terse but precise.
- **Emotional goal**: Calm confidence while agents are working — *"I can see everything, nothing is hidden, I know exactly what each agent is doing."* The UI should feel like mission control: dense but legible, alive but not anxious.
- **Three-word personality**: Cockpit · Command center · Instrument panel.

### Aesthetic Direction
- **Theme**: Single custom DaisyUI theme `jat`, dark-leaning, built on OKLCH tokens. `--anim-*` semantic variables define primary (blue 240°), success (green 145°), warning (amber 85°), error (red 25°), info (cyan 200°), secondary (violet 280°). Neutrals are tinted toward the blue hue for subliminal cohesion.
- **Typography**: Workhorse sans for body/UI, `ui-monospace` reserved for data, IDs, code, and agent output — *not* used as shorthand for "technical vibes."
- **Motion**: Rich, purposeful animation system already in `app.css` — 3D slide-in/out for list entrances, task state glows (blue/amber/green/gold), radar sweeps for live agent states. Every animation communicates a state change; none are decorative. Respects `prefers-reduced-motion`.
- **Reference feel**: Bloomberg terminal, tmux, flight-sim HUDs, synthesizer panels — tools that pack maximum signal per square inch and treat expert users with respect.
- **Anti-references (must NOT look like)**:
  - **Generic SaaS admin panels** — no Bootstrap/Material/Ant dashboards, no identical rounded stat cards, no default-blue primary buttons against gray sidebars.
  - **"AI product" slop** — no cyan-on-black, no purple→blue gradients, no neon glow borders, no glassmorphism as decoration, no chatbot-shaped empty states.
  - **Consumer productivity apps** — no Linear/Notion/Asana airy-whitespace pastel look, no friendly illustrations, no onboarding tooltips, no rounded-corner animated mascots.
  - Also avoid: retro-terminal cosplay (pure monospace, CRT scanlines, ASCII-as-decoration), nested cards, hero-metric layouts, centered-everything symmetry.

### Design Principles

1. **Density with hierarchy.** Pack signal tightly, but make the most important element at each level unmissable via space and weight. Information density is a feature — clutter is not.
2. **Space has meaning.** Tight grouping = related. Generous separation = a new section or concern. Never use equal spacing everywhere; rhythm is how the eye navigates a dense interface.
3. **Motion is signal, not decoration.** Every animation communicates state change (task entering, agent starting, work progressing, session closing). If an animation doesn't mean something, remove it.
4. **Semantic color, restrained palette.** Use the `--anim-*` tokens — blue for active/primary, green for success, amber for in-progress, red for error, cyan for info. Chroma is a tool for meaning, not flourish. Never gradient-ify text or metrics.
5. **Respect the expert.** No tooltips explaining obvious affordances, no hand-holding empty states, no nag modals. Terse labels, keyboard-first, trust the user. When in doubt, cut words and cut chrome.
